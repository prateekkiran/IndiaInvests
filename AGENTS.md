# AGENTS.md — Operating protocol for this repository

**This file is the contract for ANY agent or LLM (Claude, GPT, Cursor, Codex, Gemini,
etc.) that works on India Investment Journey. Read it fully before touching anything.
Git is the single source of truth for this project — not any local folder, chat history,
or memory.**

---

## 0. Golden rule: Git is the source of truth

The local working copy on any machine is disposable and may be stale or deleted between
sessions. The authoritative state of the project lives in the GitHub repository on the
`main` branch. Therefore every session MUST begin by syncing *from* git and MUST end by
syncing *to* git. Never assume the local files you were handed are current — verify
against `origin/main` first.

Repository: `https://github.com/prateekkiran/IndiaInvests` (branch: `main`)
Live site: `https://prateekkiran.github.io/IndiaInvests/` (auto-deployed from `main`)

---

## 1. START OF SESSION — check in from latest git (MANDATORY)

Before reading code, planning, or making any change, bring the local copy to exactly
match the remote:

```bash
cd "<repo>"
git fetch origin
git status                       # note anything uncommitted/untracked from a prior session
git stash -u                     # ONLY if there is unfinished local work you must preserve
git checkout main
git pull --rebase origin main    # local now matches origin/main
git stash pop                    # ONLY if you stashed above; resolve conflicts now
npm install                      # deps may have changed since last session
npm test                         # baseline must be green BEFORE you change anything
```

If `npm test` is not green on a clean checkout, STOP and report it — do not build on a
broken baseline. Treat whatever is on `origin/main` as correct and current; treat your
own memory of the project as a hint that must be re-verified against the code you just
pulled.

A convenience script does the whole sync-and-verify in one step:

```bash
bash project-sync.sh            # fetch, rebase, install, test — safe to run anytime
```

## 2. DURING THE SESSION — commit as you work

- Make small, coherent commits as each unit of work becomes correct — do not accumulate a
  giant uncommitted tree. Each commit should leave the project in a buildable state.
- **Quality gate before every commit:** `npm run build` (runs `tsc -b` then the Vite
  build) must pass, and `npm test` must stay green. The build is the authority on
  TypeScript correctness; bracket/paren spot-checks are not a substitute.
- Write clear commit messages in the imperative mood (e.g. `Add SWP calculator`,
  `Fix XIRR coverage gating`).
- Pushing to `main` triggers the GitHub Actions deploy (see §5). It is fine — and
  encouraged — to push working increments; a red Actions run never corrupts the live site
  (the previous good build stays up).

## 3. END OF SESSION / SWITCHING SESSIONS — sync to git (MANDATORY)

Before you finish, hand off, or the user switches to a different agent/LLM/session, the
working tree MUST be fully committed and pushed so that `origin/main` is the complete,
latest state and the local folder can be safely deleted:

```bash
git add -A
git commit -m "<what changed this session>"
git pull --rebase origin main    # fold in anything that landed remotely
git push origin main
git status -sb                   # MUST show: "## main...origin/main" with no ahead/behind
```

The session is only "checked in" when `git status` reports a clean tree and the branch is
up to date with `origin/main`. Only then is it safe to delete the local copy. Run
`bash project-sync.sh "message"` to do all of this in one step.

**Leave no work only on local disk.** If you created files, they are committed. If you
changed deploy/config, it is committed. The next session will start from git and must find
everything.

## 4. What is disposable vs. durable

Durable (in git — the only thing that survives): everything under `src/`, `public/`,
`index.html`, config (`vite.config.ts`, `tsconfig*.json`, `package.json`,
`package-lock.json`), `.github/workflows/`, docs (`README.md`, `HANDOFF.md`, this file),
`sample-data/`, and the PRD.

Disposable (git-ignored, regenerated by `npm install` / `npm run build`): `node_modules/`,
`dist/`, `dev-dist/`, `.netlify/`, `.preview/`, `coverage/`. Never rely on these persisting
and never commit them.

## 5. Deploy model (do NOT reintroduce Netlify)

Deployment is GitHub Pages via GitHub Actions (`.github/workflows/deploy.yml`): every push
to `main` runs tests, builds, and publishes `dist/` to Pages. This is deliberately
credit-free — **do not** route deploys back through Netlify or any credit-metered host.
The leftover Netlify artifacts are inert; `.netlify/` is git-ignored. `vite.config.ts` sets
`base: "/IndiaInvests/"` to match the Pages sub-path, and the app uses hash routing so deep
links work with no SPA server config. If the repo is ever renamed, update `base` to match.

## 6. Non-negotiable product principles (from the PRD)

Keep these true in any change — they are the point of the product:

- **Client-side only.** No backend, no external/live-data API calls, no provider logins,
  nothing uploaded. Valuations come only from imported statements and user-entered prices.
- **Evidence over polish.** Never fabricate data to fill a chart. Distinguish *actual* from
  *projected* everywhere. Gate performance (XIRR etc.) on adequate coverage and say
  "unavailable" with a reason rather than inventing a number.
- **Educational, not advisory.** No "best fund" scores, no buy/sell recommendations.
  Projections are illustrative and labelled "assumed", never "guaranteed"; they are pre-tax.
- **Privacy.** PDF passwords live in memory only — never logged or persisted. Keep the
  encrypted-vault model intact. Keep CSV exports formula-injection-safe.
- **Motion must degrade.** All animation goes through `src/anim/motion.ts`, which honors
  `prefers-reduced-motion` and falls back to final state on any error. Never let animation
  hide content or block a render.
